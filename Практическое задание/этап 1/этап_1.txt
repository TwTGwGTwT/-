Короткий отчёт:

1. Клиент отправляет запрос.
Пользователь (браузер или curl) формирует HTTP-запрос: метод (GET, POST…), путь (/, /ping), заголовки и тело. Запрос уходит на localhost:8080.


2. Сервер принимает соединение.
http.ListenAndServe(":8080", mux) слушает порт 8080. При входящем соединении Go создаёт *http.Request — объект, в который упакованы все данные запроса: метод, URL, заголовки, тело, параметры.


3. Маршрутизатор выбирает обработчик.
http.ServeMux сопоставляет путь из запроса с зарегистрированным обработчиком:
	/ -> homeHandler
	/about -> aboutHandler
	/ping -> pingHandler
Если путь не найден — mux автоматически возвращает 404 Not Found.


4. Обработчик выполняет логику.
Выбранная функция pingHandler получает два аргумента:
	w http.ResponseWriter — «труба», через которую сервер пишет ответ;
	r *http.Request — данные запроса.
Внутри pingHandler:
1) Проверяет r.Method — если не GET, пишет заголовок Allow: GET, статус 405 и сообщение об ошибке, затем выходит.
2) Если GET — вызывает w.WriteHeader(200) (задаёт статус-код) и fmt.Fprintln(w, "pong") (пишет тело ответа).


5. Сервер формирует и отправляет ответ.
Go автоматически собирает ответ из того, что обработчик записал в ResponseWriter:
	статус-код (200, 405, 404…);
	заголовки (Content-Type, Allow и т. д.);
	тело (текст, который вернул обработчик).
Готовый HTTP-ответ уходит обратно клиенту по тому же TCP-соединению.


6. Клиент получает ответ
Браузер отображает тело, curl выводит текст и/или заголовки. По статус-коду клиент понимает результат: 200 — всё ок, 405 — метод не поддерживается, 404 — путь не найден.
